# Combat VFX Stage 3.1：第一次施放不卡頓（1% Low）＋共用資產交接（Claude C）

日期：2026-11-28　分支：`feature/combat-vfx-stage3`（最後驗證 commit c660105，CI run 46119587063，**314 項全部通過**）
部署：**暫停中**（`.github/cvfx-deploy-hold`）。本批只跑 CI，沒有更新 gh-pages、沒有新增預覽。

## 1. 為什麼做
iPhone 實測 Stage 2／3：平均 FPS 58.7～59.5，但 **1% Low 只有 29～30.6**。平均很順、偶爾掉一格，典型原因是第一次用到某個特效時才建立網格／粒子系統、才編譯 shader。

## 2. 做了什麼（不改技能、動畫、特效美術、介面、角色）
1. **特效預熱** `VfxSystem.prewarm()`
   - 載入時把 34 種特效（自己＋其他玩家簡化版）、3 種投射物、暴擊各生成一次，共 66 個，每 16 個畫 1 格（共約 5 格）後收回物件池。
   - 不受同時特效上限影響；預熱的預算統計會歸零。
   - 最長 15 秒保護：再慢也不會擋住開機。
   - `&prewarm=0` 可以關掉預熱做對照。
2. **淡入淡出與拖尾預熱**：怪物死亡淡出、重生淡入用的半透明材質版本，以及武器拖尾，也在載入時先編譯。
3. **傷害數字**：DOM 元素在載入時就建好，戰鬥中不再新建。
4. **音效**：載入後閒置時先產生雜訊與殘響緩衝（約 20 萬取樣），第一次點擊只要恢復播放。AudioContext 在點擊前維持暫停，符合 iOS 規定。

## 3. 結果（CI 實測：載入後施放 6 個技能＋6 種職業特效＋切到白天場景）

| | 施放期間才編譯的 shader | 預熱耗時（CI 軟體繪圖） |
|---|---|---|
| 關閉預熱（對照） | **10** | — |
| 開啟預熱（Chromium） | **3** | 1.3 秒 |
| 開啟預熱（WebKit） | **3** | 3.1 秒 |

- 剩下 3 個是場景材質的半透明＋霧變體，來源還在追。
- 原本 10 個裡有 7 個是特效、粒子、發光層或拖尾，已全部消除。
- iPhone 有 GPU，預熱只畫約 5 格，預期遠低於 CI 時間（**未驗證**）。
- 1% Low 要在 iPhone 實機量測；CI 沒有 GPU，無法代表（**未驗證**）。
- 效能矩陣（32 人靜態，CI）照舊：Stage 3 Draw 184、三角面 101 萬；Stage 2 188／136 萬；Stage 1 做法 1,083。
