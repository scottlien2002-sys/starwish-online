## 3. 多人功能（伺服器權威）

| 需求 | 做法 |
|---|---|
| 不同性別、髮型、髮色、裝備 | 第一次建立角色時採用，伺服器用單機版同一個 `parseAppearance` 驗證後存進資料庫；之後以伺服器資料為準 |
| 同地圖互相看見、不同地圖互不可見 | 每張地圖是獨立房間（`village-1`、`starsprout-1`…，滿 50 人自動分流） |
| 位置、朝向、造型、動畫 | 位置／朝向來自伺服器；Idle／Run 由速度決定；Attack／Hurt／Death 是動作事件（序號遞增＝播一次） |
| 移動自然、不瞬移、不滑步 | 遠端插值（伺服器時間 −100 ms）；跑步動畫播放倍率依畫面上的實際移動速度 |
| 沒有跳躍按鈕 | 沿用 A 的規則（E2E 檢查） |
| 走入傳送陣自動換地圖、雙向 | 伺服器判定踩入（A 的同一組傳送陣資料），通知客戶端後沿用 A 的切換流程 |
| 換地圖保留外觀與資料 | 角色資料在伺服器；換頁後用憑證接回同一角色 |
| 斷線重連 | 30 秒保留；自動重連（0.5→8 秒），完整重新同步 |
| 防重複登入 | 同一角色新連線登入時舊連線被踢，且不會自動重連 |
| 防偽造移動、不因送快而變快 | 客戶端只送方向與步數；伺服器依自己的時間預算計算，超量丟棄；碰撞與合法區域在伺服器判定 |
| 倒地與復活 | 倒地中伺服器拒收移動；只有倒地中才能要求回村復活（由伺服器傳送） |

**戰鬥說明**：怪物 AI、命中、血量目前仍是各自裝置的單機行為（畫面有標示）。伺服器只轉發動作外觀，不採用任何傷害或血量數值。多人權威戰鬥在 Stage 8.2。

## 4. 資料庫（PostgreSQL 已接入）

- 伺服器有 `DATABASE_URL` 就用 PostgreSQL（`PgStore`），沒有就用記憶體。啟動時自動套用結構（可重複執行）。
- 已持久化：角色唯一 ID（UUID）、名稱、性別、外觀／武器、等級、經驗、地圖、位置、朝向、版本號、工作階段鎖、登入憑證（只存雜湊）。
- 背包：道具 UUID、冪等給予／消耗、版本檢查的接口已完成並測試；**遊戲內背包仍是本機測試資料**，Stage 8.3 改由伺服器。
- 測試資料隔離：每筆角色有 `realm`（test／prod），所有查詢都加條件；測試伺服器固定 test，正式資料區需要另外設定才能啟用。建議正式版另建資料庫。
- 單機存檔不會匯入線上資料；多人模式的本機暫存使用獨立的鍵（`mp81:` 前綴），單機存檔不受影響。

## 7. 已知限制
1. 軟體繪圖的 CI 只有約 3～5 FPS，所以 E2E 裡的延遲數字（RTT 200 ms 以上）是測試機很慢造成的，不代表 iPhone 的實際表現。
2. 畫面低於 10 FPS 時，角色移動會變慢（沿用 A 的每幀時間上限 0.1 秒；單機版相同）。
3. 同一個瀏覽器分頁的登入憑證存在 sessionStorage：關掉分頁後再開會建立新角色（測試期間的設計）。
4. 洛恩對話會讓所有人看到他停下（伺服器限制：10 秒沒有回報自動恢復、最長 90 秒）。
