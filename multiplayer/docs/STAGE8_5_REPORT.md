## 2. 帳號系統

**伺服器（`multiplayer/server/auth/`）**
- 密碼：scrypt（N=16384、r=8、p=1、32 bytes、每個帳號隨機 salt），資料庫只存雜湊；比對用固定時間比較；帳號不存在時也做一次同成本的假比對（回應時間一樣，不會洩漏「這個帳號存在」）。
- 帳號名稱：3～20 字（英文小寫、數字、底線），不分大小寫唯一；密碼 8～128 字、不能和帳號相同。
- 登入憑證：32 bytes 隨機值，伺服器只存 SHA-256 雜湊；有效 30 天；登出立即撤銷。
- 登入失敗：同一帳號連續 5 次 → 鎖定 5 分鐘（423）；同一 IP 每分鐘 12 次 → 429。帳號錯、密碼錯都回同一個錯誤，不透露哪一個錯。
- 防冒用：WebSocket 連線帶登入憑證＋角色 id；角色不屬於這個帳號 → 拒絕（`not_your_character`）；帳號角色不能用舊的訪客重連憑證登入（`auth_required`）。
- 重複登入：同一角色第二個連線登入 → 舊連線被踢（`replaced`）且不自動重連。
- 帳號與角色分開：`accounts`（帳號、密碼雜湊、鎖定）／`account_sessions`（憑證雜湊）／`characters`（`account_id` 關聯）。每個帳號最多 4 個角色（測試設定；同時建立也只會成功 4 個，資料庫帳號列鎖）。
- 預留選角／建角：`GET /auth/me` 回傳角色清單、`POST /auth/characters` 建立角色、連線時帶 `cid` 選角色。正式畫面之後只要決定 `cid`。
- 訪客模式保留（測試方便）；`MP_ALLOW_GUEST=0` 關閉後只能用帳號。`MP_TRUST_PROXY=1`（Render 自動）時從 X-Forwarded-For 取得真實 IP。
- 測試帳號都在 `realm=test` 資料區，不會混入未來正式玩家資料。

**遊戲畫面（測試用，非正式美術）**：網址加 `&login=1` 顯示登入／註冊視窗；伺服器關閉訪客時自動顯示；登入一次後重新整理會自動登入同一角色；`&logout=1` 登出。

## 3. 伺服器權威

既有（8.2～8.4）＋本階段新增測試，全部由伺服器決定、不採用客戶端數值：
- 移動：客戶端只送方向，伺服器依時間預算移動（加速封包、一次送超長步數、序號跳到極大值、過期地圖世代都無效），位置永遠在合法區域。
- 攻擊：距離（從怪物身體外緣）、攻速、技能冷卻、施放中不能再施放、錯誤武器、未知技能。
- 傷害、血量、死亡、經驗、掉落：伺服器結算；擊殺只結算一次；重送同一指令回原結果；偽造的掉落物 UUID 撿不到；活著不能要求復活。
- 客戶端附帶的 hp、level、gold、exp、atk、aspd、speed、x、z 等欄位一律忽略。
- 約 400 種格式錯誤封包（錯誤型別、極大數字、深層巢狀、二進位、200 KB 超大訊息）：伺服器不當機、tick 持續、其他玩家照常移動，惡意連線被斷開。

## 4. 技能位移同步（測試設定）

- 位移距離＝Claude C 展示動作的根運動 × `SKILL_DISPLACEMENT_TEST` 倍率（目前全部 ×1，上限 3 m）。**正式六職業技能數值尚未定案，這些都是測試值。**
  - 跳斬 1.2 m、突進 0.6 m、三段連擊 0.555 m、旋風斬 0.25 m、魔法彈／星隕 0。
- 起點＝伺服器位置；方向＝施放朝向；施放時整條路徑用 Claude A 的 `FieldTerrainQuery` 每 5 cm 檢查（地形可行走＋樹、岩石、建築碰撞）；第一個不能站的點之前就停下，不滑行、不穿牆、不越過溪流與地圖邊界。
- 伺服器每 tick 依時間把角色沿路徑移動；施放事件帶「驗證後的終點」給所有玩家 → 大家看到同一個位置。
- 位移期間一般移動輸入照算序號但不移動（不會邊跳斬邊走，也不會結束後補走）；施放者自己的畫面暫停移動輸入，由伺服器快照平滑追上。
- 一般移動仍然沒有跳躍。
- 網址 `&mpskill=leap_slam`（或 charge_burst、whirlwind）可把技能鈕換成其他展示技能（測試用）。

## 5. 背包、裝備、倉庫、交易

- 交易指令 `trade`：`offer`（對方 pid、自己的道具 uid＋版本、金幣）→ 對方 `accept`（對方的道具、金幣）→ 伺服器一次原子交換；`cancel` 取消。
- 防護：道具必須在自己背包、未裝備、版本與現在相同；金幣不能負數、不能超過持有；一人同時只有一個邀請；同一筆交易同時按兩次、重送、完成後再按，都只成交一次；斷線、換地圖、60 秒過期自動取消；距離 8 m 內（測試設定）。
- PostgreSQL：兩邊角色依 id 順序鎖定、道具鎖定、金幣紀錄、交易紀錄（`trade_log`）、雙方請求紀錄，同一個資料庫交易寫入；失敗就全部不變。
- 背包、裝備、倉庫既有規則不變（倉庫只在村莊、裝備中不能放倉庫、換武器後技能限制跟著改）；裝備與鑑定規則沒有更動。
- 重連後伺服器重新送完整背包、金幣、裝備（與資料庫一致）。
- 尚無正式交易畫面（之後的 UI 只要呼叫這組指令）。

## 8. 已知限制

- 登入畫面是最簡易測試視窗，不是正式美術；正式選角／建角畫面尚未製作（伺服器介面已預留）。
- 沒有密碼重設、Email 驗證、兩步驟驗證；登出只撤銷目前這個憑證（「登出所有裝置」尚未做）。
- 訪客角色不能升級成帳號角色；登入速率限制存在伺服器記憶體（目前只有一台伺服器，夠用；多台時要改共用儲存）。
- 技能位移只沿施放方向直線（旋風斬的旋轉不改變路徑）；怪物與其他玩家不會擋住位移（只有地形與碰撞物）；村莊沒有技能。位移距離是展示動作 × 測試倍率，不是正式數值。
- 施放者自己的畫面靠伺服器快照平滑追上（約 50 cm 內的平滑），iPhone 上的實際觀感尚未實機確認。
- 交易只有伺服器介面、沒有畫面；交易規則（8 m、60 秒、最多 8 件）是測試設定；倉庫仍只在村莊；拍賣、郵件尚未做。
- 效能數據只到伺服器端（同一房間的機器人）；畫面效能以 8.4 的渲染基準為參考，iPhone 實機數字由使用者填寫。
- Render 沒有部署；`render.yaml` 仍指向 8.4 分支。8.5 伺服器啟動時會自動套用資料庫結構 8.5（可重複執行），部署前需另外協調。
