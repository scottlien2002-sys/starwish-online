**避免重複播放特效**
- 伺服器每個戰鬥事件加上房間內遞增序號 `q`（協定向下相容）。
- 用戶端 `CombatEventDedupe`：同一個序號只處理一次；每次重新連線時重設（伺服器可能重啟）。
- 掉落物不去重：重新同步時伺服器會刻意重送地上的掉落物，畫面以 UUID 判斷。
- 已接到目前的多人戰鬥畫面（`MpFieldCombat`），並用在新的 CombatFx 橋接。
- 測試方式：同一串事件每個送兩次，畫面呼叫次數與只送一次完全相同（三位玩家各 156～163 次）。

## 4. 追蹤：WebKit 位置紀錄差異、共用資產遷移測試的時序問題

**新增的追蹤工具**
- 伺服器：每位玩家的位置稽核紀錄（最近 20 筆），記錄換地圖、過期地圖輸入、序號跳號、超量步數、超速、非法位置、技能位移被擋。
- 用戶端：≥ 20 cm 的位置校正紀錄。
- E2E：記錄每次頁面重新載入的時間，並把以上紀錄放進結果。

**WebKit 與 Chromium 的位置紀錄差異（run 46143591896）**

| | Chromium | WebKit |
|---|---|---|
| 用戶端 ≥ 20 cm 校正 | 0 | 0 |
| 伺服器超速／非法位置 | 0 | 0 |
| 過期地圖輸入（換地圖瞬間送出的舊地圖移動，伺服器丟棄） | A 1～2、B 1～3 | 0 |
| 整個 E2E 時間 | 約 486 秒 | 約 151 秒 |

- 差異只有「過期地圖輸入」：Chromium 在 CI 用軟體繪圖、每秒只有 1～3 格，換地圖時已送出的移動比較多，伺服器依設計丟棄。
- 沒有任何錯誤位置。WebKit 較快所以是 0。

**共用資產遷移測試的時序問題**
- 先前失敗的原因：CI 很慢（約 1 FPS、延遲 1.2 秒）時，B 在讀掉落物數量的同一刻被怪物打倒、由伺服器送回村莊（頁面重新載入）。這是正常規則，是測試讀取時機的問題。之前已改成容許這種情況。
- 本批追蹤到相關問題：慢速時，「走回營地傳送陣」途中玩家也可能被打倒、由伺服器復活回村，舊檢查會把它當成「走傳送陣」。
  - 已改成依伺服器紀錄如實標示是走傳送陣還是倒地復活。
  - 另新增伺服器整合測試，確定「原野營地傳送陣 → 星芽村」這個方向（以前只測了村莊 → 原野）。
